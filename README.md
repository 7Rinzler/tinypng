# tinypng

`tinypng` is an unofficial, safety-first command-line client for the [Tinify Developer API](https://tinify.com/developers). It compresses, converts, and resizes local images with deterministic file planning, non-destructive defaults, machine-readable output, and explicit approval before paid usage.

The npm package is `@coding-tech/tinypng`; the installed command and intended repository name are both `tinypng`.

## Requirements

- macOS for Keychain-backed credential storage
- Node.js 20.19 or newer
- A Tinify Developer API account

Other operating systems can use the `TINIFY_API_KEY` environment variable. Native credential storage outside macOS is not included in version 0.1.

## Install from this repository

```sh
npm install
npm run check
npm install --global .
tinypng setup
```

`tinypng setup` asks macOS Keychain to capture the API key securely, validates the account with `api.tinify.com`, shows current monthly usage, and installs the bundled Codex skill in `${CODEX_HOME}/skills/tinypng` or `~/.codex/skills/tinypng`.

The key is never accepted as a command-line argument. For CI or a temporary non-Keychain session:

```sh
TINIFY_API_KEY="..." tinypng status
```

Environment credentials take precedence over Keychain credentials.

## Account status

```sh
tinypng status
tinypng status --json
```

Tinify exposes the number of compressions used in the current calendar month. The CLI calculates the remainder of the published 500-compression free allowance. Tinify does not expose card state or prepaid-bundle balance through its documented API, so `totalAvailable` is `null` in JSON output.

## Optimize images

The default is deliberately non-destructive:

```sh
# photo.png -> photo-optimized.png; photo.png remains unchanged
tinypng optimize photo.png

# photo.png -> photo.avif; photo.png remains unchanged
tinypng optimize photo.png --format avif

# Process supported images in a directory
tinypng optimize ./images --recursive
```

Supported format values are:

- `same` — compress in the source format; this is the default.
- `avif`, `webp`, `jpeg`, `png`, or `jxl` — request one output format.
- `smallest` — ask Tinify for the smallest supported result.
- A comma-separated list such as `avif,webp,jxl` — ask Tinify for the smallest candidate.

If a dynamically selected result uses the source format, the filename receives `-optimized`. If it uses another format, the filename receives the returned extension. The CLI aborts before network processing when any possible output already exists or two inputs can produce the same output.

### Destructive mode

```sh
tinypng optimize ./images --recursive --replace-originals
```

`--replace-originals` is explicit destructive authorization:

- A same-format result atomically replaces its source after verification.
- A converted result is placed first, then the differently formatted source is deleted.
- On an API or verification failure, the current source remains in place and temporary files are removed.

There is no persistent setting that makes destructive behavior the default. Agents must obtain explicit user authorization before adding this flag.

### Dry runs and JSON

```sh
tinypng optimize ./images --recursive --format avif --dry-run
tinypng optimize ./images --recursive --format avif --dry-run --json
```

A dry run resolves inputs, possible output names, collisions, estimated credit use, possible deletions, and paid-credit requirements. It validates the Tinify account to obtain the current monthly count, but it does not upload or change images.

`--json` prints a versioned object in deterministic input order and never prompts. It includes paths, destructive state, planned outputs, sizes, dimensions, hashes, usage, approval state, and structured errors. Secrets are never included.

## Resize

Tinify's native methods are exposed without local pixel manipulation:

```sh
tinypng optimize photo.png --resize scale --width 800
tinypng optimize photo.png --resize fit --width 800 --height 800
tinypng optimize photo.png --resize cover --width 800 --height 800
tinypng optimize photo.png --resize thumb --width 800 --height 800
```

- `scale` requires exactly one dimension.
- `fit` requires both dimensions, preserves aspect ratio, and does not add padding; the result may not be square.
- `cover` requires both dimensions and crops to the requested aspect ratio.
- `thumb` requires both dimensions and uses Tinify's subject-aware algorithm. It may crop or add background space, but Tinify does not guarantee that added space will have a chosen color or transparency.
- Tinify does not upscale images.

`--background white`, `--background black`, or `--background '#RRGGBB'` fills existing transparency during an explicit conversion. It does not control background generated by `thumb`.

```sh
tinypng optimize transparent.png --format jpeg --background white
```

When converting a potentially transparent image exclusively to JPEG, the CLI requires a background unless local metadata confirms that the source is opaque.

## Free and paid credits

The CLI estimates:

- One credit for plain same-format compression.
- Up to two credits for a conversion, resize, or combined derived output.

The API's returned monthly count is authoritative. Before processing, the CLI separates planned credits into free and paid portions. Pricing constants in version 0.1 are dated 2026-09-24:

- First 500 monthly compressions: free
- Compressions 501–10,000: USD 0.009 each
- Compressions above 10,000: USD 0.002 each

Always verify current rates at [tinify.com/pricing/api](https://tinify.com/pricing/api).

An interactive terminal requires the exact phrase `APROBAR N` before a run that may use paid credits. JSON, CI, and agent runs never prompt and require a per-run ceiling:

```sh
tinypng optimize ./images --recursive --format avif --approve-paid 12
```

The approval is not persisted. If the account count changes and the next image could exceed the approved ceiling, processing stops before that image starts. Adding a payment card or purchasing credits must be done manually in the Tinify dashboard.

## Credential and skill management

```sh
tinypng config set-key
tinypng config delete-key

tinypng skill install
tinypng skill status
tinypng skill remove
```

The skill installer only updates or removes directories marked as owned by this package. It refuses to replace unrelated content.

## Exit codes

| Code | Meaning |
| ---: | --- |
| `0` | Successful command or dry-run plan |
| `1` | Image processing failed or the batch completed partially |
| `2` | Invalid arguments, configuration, input, or output collision |
| `3` | Account, quota, or required financial approval problem |
| `4` | Tinify service or network failure |

## Privacy and determinism

The API key is sent only to Tinify over HTTPS during validation and image operations. The CLI has no telemetry and does not put credentials in project files, reports, or logs. Images are necessarily uploaded to Tinify when a real optimization runs.

Determinism covers input discovery, ordering, options, output naming, collision checks, atomic placement, hashes, JSON structure, credit planning, and approval ceilings. Tinify is an external service and may update its compression engine, so identical bytes across different service versions cannot be guaranteed.
